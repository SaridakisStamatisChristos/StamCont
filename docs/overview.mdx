# Overview

StamCont provides a shared agent runtime beneath multiple developer surfaces rather than maintaining separate execution semantics for each UI.

## Surfaces

### CLI

The CLI uses the canonical Core AgentLoop and durable session store. It supports persisted sessions, resume, tool execution through AgentKernel, context planning, compaction, and canonical terminal semantics.

### IDE / GUI

The IDE/GUI surface projects the same canonical runtime into interactive presentation and approval UX. Durable Core state remains authoritative once a session exists.

### Subagents

Subagents execute as child kernel sessions. Their effective authority is constrained by the parent session; they are not an independent privilege or orchestration bypass.

## Execution profiles

| Profile | Workspace | Shell | Network | Approval |
| --- | --- | --- | --- | --- |
| Plan | Read-only | Sandboxed | Restricted | Always |
| Interactive | Read/write | Sandboxed | Restricted | Policy-driven |
| Full Access | OS-user scope | Host | Full | No per-command kernel approval |

## Persistence and resume

Durable sessions use an append-only authoritative log with rebuildable derived indexes, snapshots, and compaction artifacts.

StamCont distinguishes safe replay boundaries from ambiguous external side effects. Work that may already have changed external state is not silently repeated after a crash.

## Inherited Continue interfaces

StamCont originated from Continue and still carries inherited UI, configuration, package, and filesystem identifiers. Some deeper documentation therefore remains useful as compatibility/reference material.

Do not interpret links to upstream Continue packages, marketplaces, or historical docs as StamCont releases. StamCont does not currently claim those upstream distribution channels as its own.
